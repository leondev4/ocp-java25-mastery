Which member wins? (reference type vs object type)

      

        

          

            
📘 Compile time — REFERENCE type: Animal

            
String name = "generic" FIELD

            
void speak() overridable

            
static info() STATIC

          

          

            
📗 Runtime — actual OBJECT: Dog (one heap object)

            
Animal part: name = "generic"

            
Dog part: name = "Rex" (SHADOWS, not replaces)

            
Dog.speak() → "Woof" vtable

            
Dog.info() (hides Animal.info)

          

        

        

      

    

  

  
🎯 The rule: instance METHODS → runtime object type wins (virtual dispatch). FIELDS and STATIC methods → reference type wins (no vtable, resolved at compile time). One question in every exam depends on exactly this.

Pipeline — elements flow ONE AT A TIME, nothing runs until the terminal op

      

        

        

      

    

  

  
🎯 Exam gold: intermediate ops (filter/map/peek/limit…) are LAZY — without a terminal op, nothing executes (peek prints nothing!). Elements flow depth-first one-by-one, so limit(2) can stop the source early (short-circuit). A stream can be consumed exactly ONCE.

The exception climbs the stack until a matching catch

      

        

        

      

    

  

  
🎯 Exam gold: an uncaught exception POPS the frame and climbs · finally runs even while the exception is passing through · a catch must match the type or a supertype · if nothing catches it → thread dies with a stack trace (frames listed newest-first).
